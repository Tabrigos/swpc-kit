# Changelog

All notable changes to this project are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[semantic versioning](https://semver.org/).

## [Unreleased]

### Added

- `swpc_kit.export.to_dict` (any model as plain data for `json.dumps`, times
  in ISO 8601 with `Z`) and `swpc_kit.export.to_records` (a product as flat
  rows for `csv` or `pandas.DataFrame`, times as UTC `datetime`), standard
  library only.
- `Grid.value_near(latitude, longitude)`: the value of the cell that holds a
  point, or `None` outside the grid; `value_at` still wants the exact centre.

- Tolerance per record in the products made of records (indices, solar wind,
  GOES, alerts): a record that cannot be read goes to the model's `skipped`
  (`swpc_kit.models.SkippedRecord`: index, field, reason) and the others are
  read. A product fails only when no record can be read.
- Plausibility limits on Dst, F10.7, the solar wind field and speed and the
  GOES fluxes, and a consistency check of the 1-minute Kp: a record beyond
  them is skipped. A storm scale in the 3-day forecast needs Kp 4.67 at
  least.
- `ParseError.reason`: the message without the location.
- The client logs a warning on the `swpc_kit.client` logger for a product
  with skipped records, and a debug line for each `304 Not Modified`.

- `Client(urls=...)` and `AsyncClient(urls=...)`: new URLs by product name,
  for a product that SWPC moved before a new version knows the address.
- `UnexpectedContent.status` and `UnexpectedContent.location` (the HTTP status
  and the `Location` of a redirect), and `SwpcError.product` and
  `SwpcError.url`, set for every error that goes through the client and shown
  in its message.

### Fixed

- The index parsers (Kp, Kp forecast, 1-minute Kp, Dst, F10.7) return their
  values oldest first, one per time, whatever the order of the file. A file
  in reverse order used to give a wrong `values[-1]` without any error.
- The solar wind `data_time` is the time of the last *active* record (with
  none, the oldest record), so `max_age` rejects data whose active spacecraft
  stopped while a backup kept reporting.
- A JSON file cut inside a literal or a number (`nul`, `-1.`) is
  `SourceNotReady`, like any other truncated file, instead of
  `UnexpectedContent`.
- Any httpx2 error of the default transports is `SourceNotReady`: a body that
  did not decode (`httpx2.DecodingError`) used to escape `SwpcError`.

### Changed

- `swpc_kit.export.geotiff.write_geotiff` writes the GeoTIFF with the
  standard library only, and needs no extra: the same file as before for
  GDAL, rasterio and QGIS (CRS, transform, values, nodata, tags, band
  description and unit, deflate). A `nodata` that does not fit in a
  `float32` is a `ValueError`.

- `AsyncClient` parses in a thread (`asyncio.to_thread`): a whole OVATION
  grid no longer blocks the event loop for most of a second.
- The arguments of `Client` and `AsyncClient` are checked when the client is
  built, with errors that say what is expected: `timeout` a finite number of
  seconds, `max_age` a positive `timedelta`, `user_agent` one non-empty
  line, the URLs of `urls` HTTP, and a transport of the right kind.
  `max_age=timedelta(0)` is no longer accepted.
- The docstrings say that `timeout` applies to each phase of a request
  (connecting, sending, each read), as httpx2 does, not to the whole call.
- A field missing from every record of a JSON product is `UnexpectedContent`
  (not this product, or a format no parser knows), as the parsers' docstrings
  say; missing from some records only, those records are skipped.
- A time that appears twice in an index series skips the second record.
- Quoted numbers must be plain decimals: `0_5`, `+5`, `nan` and `inf` are no
  longer read as numbers.
- The undocumented flags of the solar wind files may be absent: they are
  then `None`.
- `swpc_kit.client` imports httpx2 only to build a default transport: with a
  custom transport it works without the `client` extra, and without it
  `Client()` says to install `swpc-kit[client]`.

- The agent skill follows the shared standard for library skills (schema 1).
  `python -m swpc_kit.skill check` compares a project's copy with the
  installed package by content hash, with line endings normalized, instead
  of by version, and reports a copy edited by hand.
- `python -m swpc_kit.skill install` needs `--target`, writes only into
  `.claude/skills/swpc-kit` or `.agents/skills/swpc-kit`, marks the copy with
  `.skill-libreria.json` (package, version, hash) and never replaces a
  directory without that marker. `--force` is gone.
- `references/api.md` is generated by the shared generator of library
  skills: one section per public module, with the signature of every parser
  (its default `source_url` is the product's URL) and of the client's
  transport types.
- `swpc_kit.codes` and `swpc_kit.export.geotiff` declare `__all__`.

### Removed

- The `geo` extra, with its numpy and rasterio (about 140 MB with GDAL):
  GeoTIFF export no longer needs them. `pip install "swpc-kit[geo]"` still
  installs swpc-kit, with a warning that the extra does not exist.

- `python -m swpc_kit.skill sync` and the `agent_skills` entry point: skills
  are no longer discovered among the installed packages. A project lists the
  libraries it wants, copies their skills and keeps the copies in git.

## [0.2.0] - 2026-10-17

Never published or tagged: the first release on PyPI comes after it. This
section was changed after its date, while the version was still unpublished.

### Added

- An agent skill bundled with the package (`swpc_kit/skill/swpc-kit/`): a
  hand-written `SKILL.md` guide for AI coding assistants and a
  `references/api.md` generated from the code by `tools/build_skill.py`.
- `python -m swpc_kit.skill install | check | show | path` to copy the skill
  where assistants look for it and to tell whether the copy is current.
- `python -m swpc_kit.skill sync`, meant for a `SessionStart` hook: brings the
  skills of every installed package that declares one in the `agent_skills`
  entry point group into `.claude/skills/`, updating and removing copies as
  packages change, in one line of output and without ever failing.
- The `agent_skills` entry point (`swpc-kit = "swpc_kit.skill"`).

## [0.1.0] - 2026-10-17

First version. Never published or tagged.

### Added

- Parsers (`swpc_kit.parse`) and frozen, typed models (`swpc_kit.models`) for
  the SWPC products of the first version:
  - indices: planetary K index (3-hour, forecast, 1-minute), Kyoto Dst, F10.7
    (30 days), NOAA space weather scales; the pre-2026 array-of-arrays
    formats are read too and give the same models;
  - real-time solar wind (magnetic field and plasma) with active-source
    selection; GOES X-ray flux with flare class and integral protons;
  - `alerts.json` messages, and the catalogue of message codes
    (`swpc_kit.codes`) checked against the official SWPC table;
  - text bulletins: 3-day forecast, geomagnetic forecast, 27-day outlook;
  - OVATION aurora and D-RAP grids in a common grid model.
- Typed errors under `SwpcError`: `SourceNotReady`, `UnexpectedContent`,
  `ParseError`, `StaleData`.
- GeoJSON export (`swpc_kit.export.to_geojson`, standard library) and GeoTIFF
  export (`swpc_kit.export.geotiff.write_geotiff`, `geo` extra: numpy,
  rasterio).
- Sync and async HTTP clients (`swpc_kit.client`, `client` extra: httpx2) with
  one method per product, conditional requests (`ETag`, `Last-Modified`),
  error classification and a `max_age` check on the time the content
  declares.
- Recorded fixtures and the tools that record them (`tools/`).
